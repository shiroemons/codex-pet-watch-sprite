# 行動エンジンの概要

このドキュメントは、Codex pet が iOS / Watch の画面上でどう動くかを、実装の細かい話に入りすぎず説明するものです。

詳しい API や状態更新の数式は [Behavior Engine](BehaviorEngine.md) にまとめています。

## 何をする仕組みか

行動エンジンは、pet の「次の行動」を決める仕組みです。

たとえば、画面の中で pet が次にどのような行動を取るかを判断します。

- 少し歩き回る
- 近くを確認する
- その場で待つ
- 手を振る
- ジャンプする
- 画面端に寄りすぎたら中央付近に戻る

完全にランダムに動くのではなく、今の状態や画面上の位置を見て、自然に見える行動を選びます。

## なぜ必要か

単純なランダム移動だけだと、pet の動きは不自然になりやすくなります。

- 画面端に張り付いたままになる
- ずっと動き続けて落ち着きがない
- ずっと止まったままで生き物らしさが出ない
- UI のボタンやパネルに重なって見づらくなる

行動エンジンは、こうした見た目の違和感を減らし、pet が画面の中で「自分で過ごしている」ように見せるためにあります。

## 判断に使うもの

エンジンは主に次の情報を見ています。

| 見ているもの | 意味 |
| --- | --- |
| 元気さ | 動き回る余裕があるか |
| 好奇心 | 探索したり近くを確認したりしたいか |
| 社交性 | 手を振るような反応をしやすいか |
| 現在位置 | 今 pet が画面のどこにいるか |
| 画面端への近さ | 端に寄りすぎていないか |
| 使える表示範囲 | ボタンやパネルに重ならず動ける範囲 |

このうち、元気さ、好奇心、社交性は時間とともに少しずつ回復し、行動すると少し減ります。

## 基本的な考え方

行動は、毎回ひとつだけ選ばれます。

1. まず、pet が動ける範囲を確認する
2. 端に近すぎる場合は、中央付近へ戻る
3. それ以外の場合は、今の状態に合わせて行動を選ぶ
4. 選んだ行動に応じて、アニメーションや移動先を画面に反映する

たとえば、好奇心が高いと探索しやすくなります。移動が続くと休みやすくなります。静止が続くと、次は少し動きやすくなります。

## 画面端に近いとき

pet が画面端に寄りすぎると、他の行動より先に中央付近へ戻します。

これは、pet が見切れたり、画面の隅で動きが分かりづらくなったりするのを避けるためです。iOS の操作パネルや Watch の小さな画面でも、pet が見える範囲で動けるようにしています。

## 動くとき

移動する行動が選ばれると、エンジンは次の情報を返します。

- どの走りアニメーションを使うか
- どこへ移動するか
- 何秒くらいかけて移動するか

右へ動くときは右向き、左へ動くときは左向きの走りになります。ほぼ上下だけに動く場合は、直前の向きを維持します。

## 止まるとき

移動しない行動が選ばれると、pet はその場で短いアニメーションをします。

| 行動 | 見た目 |
| --- | --- |
| 休む | 待つ、または通常の待機 |
| 挨拶する | 手を振る |
| ジャンプする | その場で跳ねる |
| 確認する | 何かを見ているような動き |

止まる時間が続きすぎると、好奇心が回復し、次に動く可能性が上がります。

## アプリ側との関係

行動エンジンは「次に何をするか」を決めるだけです。

実際に画面で pet を動かす処理は、iOS / Watch の画面側が担当します。

- 一定間隔でエンジンに次の行動を聞く
- 返ってきたアニメーションを表示する
- 移動先がある場合は、その位置へ滑らかに動かす
- ドラッグ中や固定フレーム表示中は、自動行動を止める

この分担により、行動の考え方と画面表示の処理を分けています。

## 調整するときに見るポイント

動きの印象を変えたい場合は、次の観点で調整します。

| 変えたい印象 | 見るポイント |
| --- | --- |
| もっと活発にしたい | 移動やジャンプが選ばれやすいようにする |
| もっと落ち着かせたい | 休憩が選ばれやすいようにする |
| 画面端に行きすぎる | 中央へ戻る判断を強める |
| 同じ動きが続く | 連続移動や連続静止の扱いを見直す |
| UI に重なる | 下部の予約領域や移動範囲を見直す |

まずは「どの行動が多すぎるか」「どの行動が少なすぎるか」を見てから、重みや移動範囲を調整します。

## いま保証していること

現在のテストでは、特に次の点を確認しています。

- 画面端にいるとき、表示範囲内へ戻る
- 動ける範囲が小さすぎるとき、無理に移動しない
- 手動の移動操作では、見た目に分かりやすく横方向へ動く
- 表示速度のプリセットで、移動時間を調整できる

より細かく「どの行動がどれくらいの割合で出るか」まで確認したい場合は、乱数の扱いをテストしやすい形に変える必要があります。
